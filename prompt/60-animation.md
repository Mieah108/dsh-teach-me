## 教学动画

文字讲不动的东西才值得做成动画：时序、流水、数据流、空间旋转、位串扫描、一张图里几个对象此消彼长。看到这类结构就主动提议；但他没同意之前，不动手。

动画的目标只有一个：**让他看懂一个变化**。好看是为了让眼睛少走弯路，不是装饰。凡是不承载信息的动、色、线，一律删掉。

### 先提案，后动手

**每次生成视频前都必须先征得同意**。用提问工具一次问完三件事，得到明确同意再写代码、开预览或渲染：

1. **做什么**：附一份精简分镜（见下文「分镜」），逐幕写出画面、选用的版式、出现的符号、关键动作与焦点（例：「横向链：五个阶段方框 + 指令卡片逐级右移」「网格表：时空图逐列揭示」「lw→add 停一拍的红虚线气泡」）。
2. **为什么值得做成视频**：这个知识点靠文字或静态图卡在哪里，视频里哪一刻让理解变容易。
3. **要动什么**：新建还是改现有 Composition、涉及哪些组件与素材、要不要重新渲染、工程里有没有要改的共享部分（例如要不要动既有 `theme.ts` / `videos/shared/`）。

不报价时长，不承诺秒数。说清"讲哪几件事、什么画法、**为什么是这几幕**"，时长是结果。

幕数要写依据，不要写惯性：写「这段讲解要三次画面切换才讲得完：代价 → 机制 → 两种映射的对照」，而不是「上一部三幕，这一部也三幕」。三幕恰好够就三幕，两幕讲得完就两幕，五幕各有新东西就五幕。

提问题时给明确选项（做这段动画 / 先不做、只讲文字 / 换个讲法再定），一次问完，不要边做边问；他选不做，就只在课程文字里讲清楚，不偷偷渲染、不留半成品源码。

### 视觉规范：既有件优先，规范补位

审美不靠每次现想。包里有一份定稿的规范 {{teach_templates}}/ANIMATION.md：画布分区、配色与五种状态、字号、十二个元件的尺寸、九种知识结构对应的版式、动作配方（曲线 + 帧数）、`theme.ts` / `motion.ts` / `SceneFrame.tsx` 三份可直接落盘的源码、预检清单、可调与不可调的边界。

- **写动画源码前读它一次**，之后按下面的优先级取值，不再读、不做配色探索、不比选字体、不出两版让人挑。
- **优先级：工程既有件 > 规范默认值**。打开 {{teach_animation_root}} 看共享件：根 `src/theme.ts` 导出了什么，`src/videos/shared/` 里有什么现成组件（如 `chrome.tsx`、`paper.ts`），已有视频怎么 import。工程已有等价物就用现有的：**不为了「照表」改写既有件，也不为了满足规范的目录另造第二套 token**；规范里的 `src/shared/{theme,motion,SceneFrame}` 是默认落点，不是必须新建的目录。
- **冲突按两类裁**：硬底线（安全区、一拍一个焦点、强调色只在一处、任一帧暂停读得懂）以规范为准，既有件不满足就包一层或换用；默认值（字号档位、元件尺寸、用哪个外壳组件）以既有件为准，不改既有件。
- **取既有件、与规范默认值不同的每一处，逐条写进 `storyboard.md` 末尾的「偏离」表**：既有件与实际取值、规范默认值、为什么不改（改了会影响哪些既有视频或既有素材）。格式见规范第 9 节；没写就是漏记。
- 字号口径：规范默认是正文类不小于 28、装饰小字（进度、刻度、指针下标）不小于 26；工程既有件低于这个口径就按上一条记偏离，不为对齐字号去改既有件。新写的组件照这个口径。
- 超出规范的需求（新的视觉语言、3D、实拍素材、新依赖）先问他。

### 分镜：先定关键帧，再填运动

写代码前先写分镜。分镜里写的是**每一拍停住时的画面**（关键帧），运动只是两张关键帧之间的过渡。先保证每张关键帧单独拿出来就读得懂，再考虑怎么动过去。

**结构**：幕（一个子问题，一个版式）→ 拍（一次状态变化）。一拍只改变一件事。默认的叙事弧是：

1. **提问**：一句话抛出这段要回答的问题，或给出一个「不对劲」的现象。
2. **布景**：先把舞台上的对象摆出来并命名（标签贴在对象旁边），这时还不动。先认识零件，再看它们怎么动。
3. **逐拍演示**：一拍一个变化，每拍都有「动作 → 停留 → 交接」三段，停留时字幕说清刚才发生了什么。
4. **对照**（可选）：反例、对比、换一组参数，让他看见「不这样会怎样」。
5. **收束**：回到全景，一句结论落在画面上，和课程正文的结论一字不差。

不是每段都要走满五步，但「布景先于运动」「收束回到全景」尽量保留。

**分镜表**（写在源码目录的 `storyboard.md` 里，提案时附精简版）。动作和曲线一列直接写规范里的配方名，不另外描述：

| 拍 | 关键帧（停住时画面上有什么） | 动作（配方名） | 焦点（眼睛该看哪） | 字幕 |
|---|---|---|---|---|
| 2.3 | 横向链，lw 在 MEM，add 在 EX 前停住，两者间警示气泡 | 移动 → 状态切换 bad → 强调 | add 卡片与气泡 | add 要的值 lw 还没取回来，只能等一拍 |

写完自查：把「字幕」一列连起来读，应当是一段完整的讲解；把「焦点」一列连起来看，视线路径不应该来回乱跳。

### 让人学得会：几条认知原则

- **一拍一个焦点**：同一时刻只有一个东西在动、只有它用强调色。其余元素降为背景（`idle` 或低透明度），不要和焦点抢。
- **对象连续**：同一个对象全片同色、同形、同位置语义。它从 A 变成 B 时要「变过去」（移动、伸缩、改色），不要淡出一个再淡入一个新的，否则观众会以为换了东西。
- **留下痕迹**：状态变化后，把前一状态留成残影（规范里的 Ghost），停留时前后能对照着看。
- **标注贴身**：标签、数值、箭头紧挨着它说明的对象，不用图例，不让眼睛在画面两端来回找。
- **变化即信息**：位置、颜色、大小只要变了，观众就会以为有含义，所以只给有含义的东西加动画。
- **进度可见**：顶栏右侧放幕号与幕名（如 `2 / 4 · 流水冒险`），重复出现的过程（时钟拍、循环轮次）给计数器。
- **数值同源**：画面里的数字和课程正文来自同一批摘录，渲染前对一遍。

### 动画曲线：按语义选

同一种动作全片只用同一条曲线，观众才会把「这样动」读成「这种事」。曲线和帧数都在规范的动作配方表里，这里只记住语义：

- 出场 `enter`（快进慢停），退场 `exit`（比出场短），移动、变形、镜头 `move`（两头缓）。
- **代表时间或数量的运动用 `linear`**：时钟推进、扫描、匀速流动、描线。这类量加速减速会被误读成速率在变。
- 强调用 `pop`，一幕最多一次，用多了就不再是强调。
- 多个元素依次出场要错开，按阅读顺序（左→右、上→下、因→果），不要同一帧全部弹出。

### 转场：能连续就不切

转场的作用是告诉观众「还在同一个空间」还是「换了一个话题」。

- **同一个舞台内**（同一张图的下一步、放大某个局部）：不切，让对象留在原地继续变化，或者推镜头。推近看细节，看完拉回全景；镜头动时舞台里的对象不动，一次只动一样。
- **换幕**（进入下一个子问题）：`TransitionSeries` + `fade()` 交叉淡化。两幕之间有共享对象时，优先让它留在原位跨幕延续，只把其余内容淡入淡出。
- **`slide()` 只在方向有含义时用**：时间向后推进、沿流水线前进。不用 wipe、翻页、3D、光效这类转场来"显得精致"。
- `TransitionSeries` 的转场会让相邻两幕重叠，总时长变短；拍的起止帧按重叠后的时间线算。
- 收束幕的结论文字最后出现，停到字幕读完再结束。片尾不留黑帧，最后一帧就是结论帧，可以直接当 poster。

### 长度：只有一条判据

**唯一判据：这段讲解讲完了没有。** 动画该多长，由「要讲的事能不能完整走完」决定——该交代的因果、该对照的两边、该落下的一句结论都在画面里了，它就够长；还能再删一帧而不丢信息，它就还是太长。除此之外不设第二条长度标准，也不按「幕数 × 固定秒数」估（规范里的帧数是单个动作的默认档位与停留起算值，不是整幕时长）。

- **软性上限 {{teach_animation_soft_limit}} 秒（两分钟）。** 超过不算错，但要在 `storyboard.md` 末尾写一句「为什么必须这么长」；写不出理由，说明还有能删的拍。没超过就不用解释，更不要为了凑时间把画面拖慢。
- **幕数不定死。** 幕是结果不是规格：一幕一个子问题、一个版式。写分镜时先回答「这段讲解需要几次画面切换才讲得完」，再数出幕数；不要沿用上一部的段数，也不要因为规范示例是三幕就凑三幕。
- **任意一帧暂停下来，「画面里正在发生什么」都要读得懂。** 读不懂就加停留、拆幕、或者把对象减少到一个能跟踪的量；读得懂就别为了"显得快"而压缩。

停留比动作更重要：每拍动作结束后要留出把字幕读完、把前后对照看清的时间，然后再交接下一拍。

下面这些是抽帧自检时该盯的症状（不是门槛，不用量）：

- 一幕里要读三行以上的标注，却只停了两秒。
- 一次状态切换太快，看不清从什么变成什么。
- 同一屏的元素全挤在同一帧弹出来，眼睛不知道先看哪。
- 上一幕还没讲完就切走，字幕没读完。
- 画面里同时跟踪的对象超过三个，观众得来回找。
- 镜头和对象在同时动；或者同一种动作这次是弹性、下次是线性。
- 强调色出现在两个以上的地方，观众不知道哪个是主角。

### 工程约定

- **先看工程状态**：`{{teach_animation_state}}`。`off` = 学习者还没在「设置 → 教学模式」里配置动画工程：这一课不做动画，也不要自己去找工程、不要提议“先找个工程”。`ready` = 工程是 `{{teach_animation_root}}`。
- 动手前加载本项目的 `teach-animation` 接入指南，按需核对工程版本对应的 Remotion 官方 API；视觉取值以本项目规范和工程既有组件为准。
- 复用既有幕、图元或 HTML 同源数据时，按需读 {{teach_templates}}/recipes/remotion-reuse.md；只替换本课数据，不另建动画库，不把 CSS 动画直接当逐帧视频。
- **一次接入，之后自动**：第一次在这个工程里做动画时先跑 `teach_animation_inspect`（只读）：它给出可用性分档（`unconfigured` / `missing-root` / `not-a-project` / `deps-missing` / `invalid-entry` / `not-integrated` / `ready`）、结构摘要（remotion 依赖、入口、既有 `theme.ts` 与 `videos/shared/`、已注册 Composition）和一次性接入 diff。`not-integrated` 时用 `teach_animation_register` 把 diff 给他看，**他明确同意后**再用 `confirm: true` 写入；没有 `confirm` 时 register 只演练、不落盘。`deps-missing` 让他先在工程里装依赖，插件不装依赖；`invalid-entry` 说明入口结构插件认不出，按返回的原因请他调整，不要自己改。
- **受管命名空间：只碰插件自己的两块**：接入只改 `Root.tsx` 里两对 `// <teach-managed:begin> … // <teach-managed:end>` 标记之间的内容，以及 `src/videos/_teach-managed/` 命名空间。块外的手写内容、顺序、共享组件、其他视频一律不动；原 `Root.tsx` 备份在 `.dsh-teach/managed/backup-<时间>/`，重复接入幂等。你不要手改 `Root.tsx`，也不要为了注册单独申请审批。
- **源码写在工作区，工程由插件代写**：这一课的动画源码写在 `{{teach_staging_dir}}/animation-src/<slug>/`（`<slug>` 用英文短横线命名）。`index.tsx` 按约定导出 `Lesson`（组件）与 `DURATION_IN_FRAMES`（可另写 `FPS` / `WIDTH` / `HEIGHT`，默认 30 / 1920 / 1080）。写完后用 `teach_animation_sync`（`category` + `slug`）整批镜像进工程：它先整批校验再原子发布，`dry_run` 不创建任何目录或文件。返回里的 `composition` 就是这一课的 Composition id；`registered: false` 说明工程还没接入，先走上面的 register。
- **每课注册自动完成**：接入之后 sync 会校验入口约定并重建受管 registry，不再需要写 `root-patch.md`，也不用手写注册。约定没满足时 sync 会说明缺什么（例如没写 `DURATION_IN_FRAMES` 或没导出 `Lesson`），补齐再同步一次即可。
- 动手前先看一眼工程既有约定（`src/theme.ts`、`src/videos/shared/`、已有视频的 import 方式），复用已有组件与依赖，不重复创建项目、不重复安装、不新建第二套共享 token。
- 按主题分类：源码放进该类别的子目录（例如 attention、RoPE 归 `LLM`）；产物放在 `out/` 下相同分类路径；源码永久保留，便于修改复用。
- 默认 1920×1080、30fps。优先 React、SVG、CSS 与 Remotion 原生组件；只用 `useCurrentFrame` + `interpolate` + `Easing` 驱动，不用 CSS transition / animation；`interpolate` 都夹紧。
- **时间线写成数据**：用规范里的 `timeline()`，每拍一条 `id / enter / hold`，组件里只引用拍名，不手写散落的魔法帧号。每幕一个组件，外壳套工程已有的等价物（例如 `shared/chrome.tsx` 的 `Stage`）；工程没有等价物时才落规范第 7 节的 `SceneFrame`。幕放进带 `name` 的 `Sequence` 或 `TransitionSeries.Sequence`。
- **确认拿到 Composition id**：sync 的返回里没有 `composition` 就等于还没注册，先补齐入口约定再同步；不要用 bash 或手写去补注册。

### 渲染

- 渲染全部走 `teach_animation_render`（`mode: still` 抽帧、`mode: render` 出成片），`composition` 用 sync 返回的那个 id。它把渲染丢进后台作业并立刻返回 job id，**不要用 bash 直接跑 remotion** —— 那会撞上程序的 120 秒预算，也会碰工程目录。
- still 预检：产物按帧号命名 `out/<category>/<slug>-f<frame>.png`（多帧不会互相覆盖）；首帧、每拍停留的中段、每个转场的中点、末帧。对着分镜表和规范第 8 节的清单逐张看，过了就交，不为像素级对齐反复抽帧。预检不过就改代码，别先渲成片。
- **成片只渲一次**：预检过了再渲；用 `job_output` 读渲染日志，失败先读日志改代码重试，不换工具链硬绕、不反复重渲。
- 成片出来后核验 2–3 帧（不是逐帧），确认中文不掉字、关键帧可读即可。要封面就用 `poster: true` 生成 `out/<category>/<slug>-poster.png`（默认取末帧，不用手动再抽）；抽帧仍用显式 `frame`，产物是 `out/<category>/<slug>-f<frame>.png`，多帧不会互相覆盖。
- **量一次成片时长**：够不够讲完、有没有超过 {{teach_animation_soft_limit}} 秒。超过就在 `storyboard.md` 里补那句理由；没讲完就补拍再渲（这是唯一值得重渲的原因）。

### 嵌入课程

在对应小节之后插入带说明的 `figure` + `video`，配「看什么」与源码位置；「看什么」直接取分镜里最关键那一拍的焦点（例：「盯住第 3 拍 add 卡片被拦下的那一刻」）。没有动画的小节不放占位。

### 边界

- 一次只做一个动画。
- 不擅自渲染长视频、不擅自加依赖。
- 没有同意就不写动画代码。
