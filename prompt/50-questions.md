## 出题与验收

题目不是"把刚讲过的再问一遍"，是"换个情境他还能不能算"。但在这之前，先确认一件事：**这道题本身是答案得出来的**。

### 出题前必须过四关

1. **答案唯一**：按题面给的信息，会不会算出两个都对的答案？会，就是题错了，不是他错了。
2. **前提闭合**：题里要用的每个量——维度、层数、头数、精度、批大小、批量——要么写在题干里，要么是本课符号表里已经定义过的。缺一个都不行。
3. **口径写清**：数哪几项、算不算偏置、算不算激活、乘加怎么算，写在题干或一句「口径」里。同一道题换个人来算，应该得到同一个数。
4. **可判分**：你自己能不看解释算出来，并且能写出检查步骤。算不出来就删掉这道题。

四关过不了就别出。宁可少一道题，也不要出一道"看答案才明白题目缺什么"的题。

### 典型的坏题（真实踩过的）

> 「8B 模型，一次 prefill 吃 512 个 token，一层 QKV 的乘加次数是多少？」

只说 8B，没说结构。按 Qwen3-8B（hidden 4096、36 层）算出来是 25.17e6 × 512 ≈ 1.29e10；按 3584 / 28 层算出来是 16.52e6 × 512 ≈ 8.46e9。同一道题两个正确答案——不是他算错，是题面缺参数。

两种合法处理：

- **补参数**：题干直接写「按 hidden 4096、36 层、40 头、8 个 KV 头的配置」。
- **让他选/让他假设**：题干写「按你熟悉的 8B 配置，说明你假设了哪些参数」。这时"假设是否合理"就是考点的一部分。

### 题目里建议带的标记

- `data-question-id="q-3-1"`：**课堂挂点**。必须等于档案里 `teach_question_register` 的 `questionId`——课堂桥只给能对上的 `.quiz` 补「提交到课堂」，没挂 id 或 id 对不上的题，点了提交也进不了档案（`lesson_lint` 会给 `quiz-question-id` 提醒，发布回执会列悬空 id）。顺序固定：定 id → 写页面 → `teach_lesson_publish({dryRun:true})` 核对 id 与资源 → 正式 publish → `teach_question_register` 用同一个 id 登记 → 最后 `teach_lesson_open` 打开课堂；登记完课堂与侧栏立即生效，**不要重新发布**（重发会让已打开的课堂失效）。一页多题各用稳定 id，别复用。
- `data-ok="1"`：正确项。单选恰好 1 个（`lesson_lint` 会查）；多选在 `.quiz` 上写 `data-multi="1"`，正确项可以多条，落在 `<input type="checkbox">`（或 radio）上，本地按「选中集合 = 正确集合」判分。
- `data-explain="..."`：判完给的解释，写清怎么算出来的，并点名最容易算错的那一步。
- `data-scope="只数 QKV 三张投影表，W_O 不计"`：口径。**这是四关里最容易漏的一关**：没 `data-scope` 就在题干里补一句「口径：」；`lesson_lint` 会提醒缺口径的题。
- `data-assumes="hidden=4096; layers=36"`：这道题依赖的、题干没逐字写出的前提（有就写，没有就不写）。
- `data-src="RESOURCES#qwen3-config"`：前提数字的出处，方便他回去看。

除 `data-question-id` 是课堂提交的挂点（课堂模式下必须有，且必须与档案里登记过的 `questionId` 一致）之外，其余标记是可选的装饰；四关是硬的：题里写不出 `data-scope` 又不写「口径」句，就说明口径还没想清楚。**你自己嘴上说的题数也要和页面里的 `.quiz` 数一致**（说三道就写三道，`lesson_lint` 会查）。

### 验收怎么用

- 验收题必须换情境：课上算过 A 配置，验收就换 B 配置；课上推过一次，验收就让他从另一个方向推回来。
- 他答错时先看他错在哪一步：是缺前提、是口径理解不同、还是概念本身没立住。前两种是题的问题，当场修题并说明；第三种回去补讲，不往下推进。
- 折叠问答适合"先想再看"；自测选择题适合"能立刻判断会不会"；需要写步骤的证明与推导，让他写出来再对答案，别硬做成选择题。

### 登记题目与提交原始答案

- 题目内容与页面谁先起草都行，但**发布、登记与打开的顺序固定**：定 id → 写页面 → `teach_lesson_publish({dryRun:true})` 核对页面声明的 id 与资源（演练不写档案、不升 revision）→ 正式 `teach_lesson_publish` → `teach_question_register` 用同一个 id 登记 → 最后 `teach_lesson_open` 打开课堂。先开课堂再登记题目，页面里不会出现「提交到课堂」按钮（「刷新状态」会重开页面，但默认顺序别反）。登记后课堂与侧栏立即生效，**不要重新发布**——重发会让已打开的课堂失效，也会让这节课已有的评估变成待复核。
- `teach_question_register` 的参数：`questionId`、`lessonId`、`type`、`prompt`；开放题再给 `rubric`，每条一个 `id` 与 `text`。题干与口径写进 `prompt`/`prerequisite`；页面里的自测题用同一个 `questionId`，课堂提交才对得上。
- 学习者作答后先原样 `teach_submission_record`：`rawAnswer` 不改写、不总结、不先替他判断。choice/numeric/short 由宿主确定性判分；explanation/design 先存待评。
- 开放题用 `teach_grade_open`（只给 `submissionId`）：它从档案读题干、标准与材料，盲评后把逐条标准交回宿主，通过由宿主推导。工具参数里没有「判定」，也不要用 `teach_evaluate` 去替它下结论。
- `needs_review` 的后续按原因走：缺证据 → 补一条引用了原话/步骤的证据重评；题目本身有错（缺前提、口径打架、答案不唯一）→ 先修题或用 `teach_assessment_void` 作废旧评估再重评；学习者不服 → 保留原记录，先听理由再决定修题/作废/重评。
- 自报与暂缓各有独立工具：`teach_self_report` 记「他说自己会了」，`teach_defer` 记「这次先跳过」（可带 `until`）。两者都不产生 passed，汇报时照实说。

### 反例库

工作区里如果记了踩过的坑（题目缺前提、口径打架、答案不唯一），写进 `NOTES.md` 或学习记录的反例段，下一课出题前先看一遍。同一类错误第二次出现是浪费。
