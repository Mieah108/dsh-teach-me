# 宿主三面：对 11-04 设计评审的处置

**对象：** `docs/reports/2026-11-04-host-ui-design-review.md`（评审 V01–V09、U01–U06、§10 证据缺口）
**结论：** 采纳其观察，重做其处方。评审抓到的语义错误全部是真错误，处方则一半以上会把这一面做成另一类界面。
**证据：** `artifacts/host-ui/after-fix/`（90 张：15 状态 × 明暗 × 宽度）、`node --test 'test/**/*.test.js'` 676 通过、`lint.mjs --app client.js` 0 FAIL / 1 WARN（路径输入等宽，DESIGN.md 已允许）。

## 二、评审观察成立、但处方不成立（按自己的判断改）

| 编号 | 评审的建议 | 实际做法与理由 |
| --- | --- | --- |
| V01 | 字阶整体拉开，页标题提到 18–20px | 只把课程名 13→14。宿主自己的设置页就是 16/14/12，把分区标题抬到 18–20 会去和宿主抢主次；层级靠间距（页头 28、组间 16/24）与字重建立 |
| V02 | 字段间 16–20、分组间 24–32 | 组内 16、组尾 24、组上 20：线两侧都不贴字，且组上留白仍大于组内 |
| V03 | 布尔选项做成完整设置行、优先用宿主开关组件 | 方框回到名字左边 8px。宿主能右端对齐是因为它每一行都有同一列控件；这里只有一个开关，右对齐只会造出一条 500px 空白 |
| V04 | 页头只留简短定位与保存状态，复杂路径进高级说明 | 页头收到两行（状态句 + 一句保存方式），路径提示一句话；没有折叠——四个字段、三个动作，再加一层只是把问题藏起来 |
| V05 | 课程名允许两行，题号信息进展开详情 | 标题保持单行 14px + 原生 `title`。侧栏列表的任务是横向比较，两行标题会把一屏可比较的课程数砍半；异常信息压成一行，且只讲学习者能懂的数量 |
| V06 | 主状态换成「评估已过期」，历史结论降低权重 | 已按这个方向做：印章是唯一强调，历史结论降为灰字「上次 未通过」，红色只留给当前有效且未通过的结论 |
| V07 | 工具栏统一高度、取消重复下划线、优先宿主按钮惯例 | 动作收敛成两种形态：一枚描边主钮 + 不带下划线的次级文字钮；三种控件形态在头部共存的问题消失 |
| V09 | 深色从宿主背景层级令牌取一档给输入框 | 不做。浅色的 `bg-layer-1/2/3` 全是 `#fff`，照做会变成「只有深色才有的解剖」，两种主题两套结构比一条安静的分隔线更糟；层级问题用 V02 的间距解决 |

## 三、不采纳的三条（性价或数据不支持）

1. **U04 的「当前课程选中态」**：宿主管不到「哪一节是当前课堂」。`ClassroomTab` 只知道自己在开哪一节，把「最后点过的一行」长期当作当前课程，会比没有选中态更误导。已做的是另一半：入口箭头常驻、题量不随悬停消失；选中态留到有真实数据源时再加。
2. **6.1 / 6.3 的高级折叠与「更多」菜单**：四个字段、三个动作，折叠只会多一次点击。
3. **§9 的验收项改造**（把三面拆成独立页面级验收）：三面是宿主里的客人，验收标准应由宿主决定；现有 bench（15 状态 × 明暗 × 宽度 + 0 pageerror）已经是可重复的对照手段。

## 四、独立复核后又改的一轮

按 V/U 清单改完之后，又让一次独立复核（只读、不看我的说明、直接读源码与截图）重看了一遍。它抓到的六条都是真的，已改：

| 问题 | 修法 |
| --- | --- |
| 设置页在 `loading` / `unavailable` 时印「这一版不做动画：还没配工程目录」——配置根本没读到 | 配置没就绪时不印生效状态句、也不画字段组：禁用控件里的默认值会被读成「已经这么选了」 |
| 课堂载入态只有一句裸文本，和选课那边的骨架行自相矛盾 | 头部一条骨架 + 一块整帧骨架（`--dsw-skeleton` 同一套），文字只留 `sr-only` 的「正在打开课堂…」 |
| 页签指南的 `coursesIntro` 在两张文案表里都不存在，宿主会把键名画出来 | 补上中英文案；`client-copy.test.js` 的扫描从 `t("…")` 扩到 `bind(NS)("…")`，正是这个缺口漏掉的 |
| `questionCount:0` 与 `missingPageIds` 同时成立时，同一行既说「本课没有练习题」又说「N 题还没登记进档案」 | 有题号不一致时不再印 0 题那句，让不一致那行自己说明；两句互相打脸的情况消失 |
| 题号不一致那行对读屏完全不可见（`aria-label` 盖住子树，`aria-describedby` 只指元信息） | 那一行补 `id` 并加入 `aria-describedby` |
| 失败态丢掉了顶部条，比空态高 20px；「重试」是灰色小字，看着不像控件 | 失败态保留顶部条与列表线，重试改成描边主钮；`role="alert"` 只包文字，按钮移出活区 |

另外两条按需要保留、按事实调整：账目行的「待批改」改成「其中待批改」（它本来就是已答里没判的那部分，并排写会被读成两个计数相加），「最近评估」补上评估日期（`ledgerOfStatus` 本来就算出了 `verdictAt`，只是没显示）。

## 五、评审没提、这轮顺手修的

- 「课程列表读不到：」「课堂打不开：」句末的冒号悬在行尾（正文换行后没有下文），改成无冒号标题句式。
- 失效原因从状态词后面挪到日期之后：折行时最安静的一句话落到第二行，第一行留给「评估已过期 · 上次未通过 · 作答 10-31」。
- 空态、失败态、载入态三者的内边距过去随标签是 `p` 还是 `div` 而变；现在只由容器决定。
- `DESIGN.md` 的间距、勾选框解剖、时长上限口径与账目行描述已按新实现更新。

## 六、仍未做（需要产品决定，不是设计取舍）

- `catalog.openable` 仍未进界面：它是「宿主有没有 `sidebar_open` 工具」，不是「这一节课能不能开」。界面上的开启动作走 `sidebarRight.openTab`，两者不是一件事，不能拿它给行上锁。
- 课堂挂载时多一次 `classroom/status` 读（本地调用，限频 60/分）；如果宿主把限频压低，这里是最先要退让的一处。
- 课程名超长仍是单行省略：这是 V05 的取舍本身，不打算改回两行。
- 课堂「已答」是按 `lessonId` 汇总的 submission，不区分题目 revision（`lib/classroom/service.js` 的口径）：旧版遗留的提交会被算进这一节的「已答 N」。界面用 `min(answered, questions)` 只是不让它溢出，不算修正；要改得动服务端的归类，不在这次前端范围内。
- 设置页的 `loading` 态只留标题 + 「读取中…」，没有再画骨架：宿主配置几乎是同步下发的，画骨架反而会闪一下；这一条与选课/课堂的骨架行不一致是故意的。
