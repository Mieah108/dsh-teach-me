# 教学模式插件宿主界面设计评审与重构建议

日期：2026-11-04（Asia/Shanghai）  
对象：`dsh-teach-me` 当前工作区版本，`0.8.0-beta.1`  
状态：设计评审与建议，尚未实施产品改动

## 1. 结论与建议顺序

建议对设置页、选课侧栏和课堂外壳进行一次集中重构。当前问题主要来自三方面：**视觉层级过于接近，信息和操作缺少清楚的分组，部分学习状态的文字超出了数据实际表达的含义。** 这些问题相互叠加，使界面虽有统一样式，却仍显得像工程表单和档案清单。

建议保留宿主字体、主题令牌、页签体系和课程隔离方式，在此基础上重新安排布局、字阶、行结构和工具操作。辨识度可以来自“清楚的课程名称、可信的学习状态、容易找到的下一步”，无需增加独立皮肤。

本轮最值得优先完成的三项设计工作：

1. **课程列表重排**：突出课程名，明确进入动作，整理历史结论、失效提示与辅助信息。
2. **设置页重新分组**：基础配置优先，高级技术选项折叠，明确保存与生效状态。
3. **课堂头部收敛**：导航、学习状态与维护操作分层，给课程本体保留完整展示空间。

状态含义错误和空态样式缺陷应与上述工作一起处理。搜索、筛选、阅读续接等能力放到后续阶段，避免把一次界面重构扩大成数据模型改造。

## 4. 美观问题分析

### V01：字号层级接近，页面没有足够明确的主次

**已测量：** 设置页标题为 16px/24px、600；分组名 14px/22px、600；字段标签 13px/20px、500；说明 12px/18px。课程名为 13px/20px、500，状态为 12px/18px。

**设计判断：** 当前字阶并非不可读，但连续几层只相差 1–2px，视觉区分主要依赖加粗。课程名、状态、字段标签容易形成相似的文字块；设置页的“页面标题”和“分组标题”也不够鲜明。

**建议：** 优先拉开职责，而非全部放大。课程名采用宿主 14px 档；设置页分组使用 14–16px，正文与控件尽量统一到宿主 14px 档；日期及简短说明保留 12–13px。设置页标题可以尝试宿主已有的 18–20px 档，但必须与真实设置页的其他分区并排核对。若宿主统一要求 16px，应保留并通过留白、字重和布局建立差异。

来源：[S1]；量测见配套 JSON。

### V02：分组上松下紧，留白节奏失衡

**已测量：** `.tsm-group` 内边距为 `20px 0 4px`。在 390px 设置页中，源码存放说明结束于 y=475，下一分组从 y=479 开始，间隔仅 4px。

**设计判断：** 每组开头留白较充裕，组尾说明却紧贴下一条分隔线；页面读起来像一系列单独堆放的字段，分组缺少完整收尾。

**建议：** 使用明确的间距角色，例如字段间 16–20px、分组间 24–32px，分隔线两侧保持可辨认的空间。取值是重构起点，最终要服从宿主设置页密度。先通过间距完成分组，再判断是否需要轻微底色。

### V03：控件关联感不足，右侧开关显得孤立

**已测量：** 桌面设置组件宽 640px；路径框宽 640px，下拉框 260px，数字框 120px。源码存放标签宽 117px，16px 复选框靠右，标签右边至复选框左边约 507px。

**设计判断：** 不同类型控件使用不同宽度是合理的；当前不足在于它们没有共同的设置行结构，最右端的复选框与左侧标签缺少视觉连接。

**建议：** 保留路径长、数字短的自然宽度，统一字段内部对齐和间距。布尔选项采用完整设置行，明确标题与说明的归属。如果宿主已有开关组件，优先使用同一组件；不要只把复选框换成自制开关。折叠高级项也能降低这组控件对主页面轮廓的干扰。

这一测量来自 640px 测试组件，不能直接等同真实宿主中的距离；真实设置列更窄时，孤立程度会减轻。

### V04：说明文字较重，页面轮廓过于零碎

**截图观察：** 页头包含状态长句与保存说明；各字段下面又有解释。中文、英文技术名、文件路径及数字范围交替出现，形成多种长度的灰色文字块。

**设计判断：** 虽然说明使用了次级色，连续出现仍会与操作区争夺注意。路径等宽字体有明确用途，但路径和目录规则占据过多可见空间时，工程感会盖过学习工具的定位。

**建议：** 页头只保留简短定位与保存状态；每项核心说明一行优先，复杂路径和工作区规则放入高级说明。保留必要事实，不通过降低对比度或继续缩小字体隐藏信息。

### V05：课程列表像记录清单，主题和行结构不够突出

**已测量：** 300px 外宽侧栏中的实际组件宽为 299px，左右内边距各 12px；课程标题可用宽度约 240px。标题单行省略，普通课程行约 61px，带失效原因及题号异常的课程行约 81px。

**设计判断：** 横线、状态词、日期和题号构成密集的小块；长课程名被截断，课程主题的视觉重量不足。不同内容产生不同行高本身没有问题，但当前额外高度主要被异常细节占用，列表节奏由异常信息决定。

**建议：** 课程名允许最多两行，标题优先于题量；下方放一个主要状态和最近提交时间。增加题号等信息时使用展开详情。以稳定的行内分区建立节奏，避免为了严格等高强行截掉课程名。

### V06：颜色把失败结论推到视觉中心

**截图观察：** 列表绝大部分为中性色，红色“未通过”成为最醒目的区域；同一行还出现浅警告底的“已失效”。

**设计判断：** 学习者先看到失败，再判断这条失败是否已过期。历史无效结论仍以鲜明错误色出现，既增加视觉噪声，也容易误读。

**建议：** 将当前有效状态作为主要标记。评估已过期时，主状态改为“评估已过期”，历史“未通过”放进详情或降低权重。失败标签若使用柔和底色，必须取宿主语义令牌，并同时保留明确文字；不能只靠颜色说明。

`artifacts/host-ui/review/courses-ready-detail.png`

图 2：课程列表中长标题截断、异常信息堆叠、0 题课程仍显示“尚未作答”等问题。合成数据只用于说明界面状态。

### V07：课堂按钮语言不一致，维护操作过于突出

**已测量：** 刷新按钮高 28px，导出／导入文字按钮高 24px；后两者使用下划线，返回是无下划线纯文字。课堂工具文字为 12px。

**设计判断：** 三种处理放在很小的头部区域中，像分别加入的控件。“刷新状态”拥有最强按钮轮廓，阅读和作答相关信息则较弱。

**建议：** 同一工具栏使用共同的控件高度与对齐方式；建议紧凑工具栏从宿主 32px 控件起步，触屏命中区单独满足要求。导航、工具按钮与链接分工明确，取消工具动作上重复的文本链接式下划线；使用宿主已有的按钮和菜单惯例。

### V08：空态和失败态呈现出不同的边距规则

**已测量：** 选课空态 `p.tsm-empty` 的计算 padding 为 0，其文字从面板左边缘开始；正常课程标题向内 12px。错误态使用 `div.tsm-empty`，保留 `16px 12px` padding，文字起点又不同。

**源码确认：** `.tsm-surface p` 的选择器优先级高于 `.tsm-empty`，覆盖了后者的段落内边距。父列表负 margin 又抵消了面板左右 padding。段落形式的可用性提示、通知行也存在 padding 被 reset 覆盖的同类问题。

**建议：** 明确 reset 与组件样式的优先级，避免依赖标签碰巧为 `div` 或 `p`。正常、空白、失败、加载状态共享内容边界；用语义结构表达状态，不用换标签来绕过样式问题。

来源：[S1]，第 237、274、277、298、1199–1203 行。

### V09：深色模式的层级主要依靠细线，区域归属偏弱

**截图观察：** 深色设置页的地面与输入框区分较轻，分组主要通过文字和横线表达。

**设计判断：** 长时间使用时风格安静，但基础配置、高级选项与编辑控件没有形成足够明确的层级。

**建议：** 先调整间距与分组；仍不足时，从宿主已有背景层级令牌中选择一档，用于输入框或小范围配置区域。不新增蓝黑配色、发光边框、透明面板或独立字体。此项为视觉建议，本文未据此宣称现有深色对比度不达标。

## 5. 直观性及状态准确性分析

### U01：没有评估结论，不等于尚未作答

**源码确认：** 选课行将空 `lastVerdict` 直接映射为“尚未作答”；catalog 分别计算最近评估与最近提交，因此已经提交而暂无结论是支持的情况。

建议以现有数据保守表达：

| 数据条件 | 建议文字 |
| --- | --- |
| 无结论，有最近提交时间 | 已提交，暂无评估结论 |
| 无结论、无提交时间，题量大于 0 | 尚未提交作答 |
| 题量为 0，且无历史作答／评估 | 本课无练习题 |
| 历史结论已失效 | 评估已过期；详情说明原因与历史结论 |
| 无法取得状态 | 状态暂不可用 |

无结论不能自动命名为“待批改”：catalog 未提供待批改数量，无结论还可能涉及评估作废等情况。0 题但有历史记录时也不能直接隐藏历史，需明确课程版本语义。

来源：[S1] 第 1207–1224 行；[S3] 第 554–583 行。

### U02：课堂里的“通过”只代表最近一次有效评估

**源码确认：** `ledgerOfStatus` 在逐题提交中按 `verdictAt` 选择最新的 `effectiveVerdict`，没有计算整课结论。界面却把这个词直接接在统计行末尾。

因此“4 题 · 已答 2 · 待批改 1 · 通过”容易让人误以为整课通过。建议改为“最近一次评估：通过”，或仅显示作答与待批改计数，将评估说明放入详情。整课通过必须有独立规则和数据支持，不在此次视觉重构中自行推导。

来源：[S1] 第 776–795、1058–1062 行；[S3] 第 419–430 行。

### U03：目录保存、运行期启用和工程可用性被压成一句话

**源码确认：** 设置页的“这一版会做动画”仅根据本地快照路径非空及上限有效性生成。运行期还会合并设置值、预设值与默认值，并且真正的工程检查另有机制。

配置读取可以取得新快照，但动画工具与对应提示词的注册发生在运行期初始化阶段。不能承诺填完即刻启用，也不能笼统要求每次修改都重启整个宿主；真实宿主是否自动重载相应行尚未验证。

建议界面至少区分：**未配置／目录已保存／工程尚未验证**。如果以后接入现有检查结果，再展示“工程可用”等状态。跨越动画开关边界时，按照真实宿主验证结果提示重新加载教学运行期。工程健康检查的 UI 接入需要额外数据连接，应列为扩展任务。

来源：[S1] 第 493–509 行；[S4]；[S5] 第 141–144 行；[S6]。

此外，当前设置页把超时要求写成“分镜超过 N 秒”。配置 schema 和动画协议实际指向**一节课动画的成片时长软性上限**，要求超出后在分镜文档中说明理由，并非给单个分镜设 N 秒上限。建议将字段及状态句统一表达为“动画建议时长上限”，只纠正宿主界面文案，不改变动画内容、时长判据或制作协议。来源：[S9]。

### U04：进入动作仅悬停可见，当前课程缺少持续选中表达

**源码确认：** 课程整行是按钮；“打开”默认隐藏，hover/focus 时出现，并替换题量。当前课程行没有根据已打开课程设置的持续选中样式。

建议保留整行点击和键盘可达，常驻一个轻量进入提示；题量不随悬停消失。当前课程的选中状态使用宿主中性底色，与 hover、焦点环区分。实现选中态前先核实宿主能否提供当前课堂 lessonId，不能把“最后点过的一行”长期当作真实当前课程。

来源：[S1] 第 283–287、1230–1249 行。

### U05：“刷新状态”实际还会重新挂载课程

**源码确认：** `refreshStatus` 同时请求 `classroom/open` 和 `classroom/status`，并增加 `frameSeq`；iframe key 随之变化。这不是仅更新顶部计数。

重挂可能影响滚动位置或尚未提交的页面内状态，但本文未在真实课程中验证影响范围。建议先准确命名为“重新加载课堂”，并放在次级工具操作中。若后续要拆成“仅更新状态”与“重新加载课程”，应单独确认行为及测试，不能在换样式时静默改变。

来源：[S1] 第 928–954、1077–1083 行。

### U06：空态和错误态没有形成完整的下一步

“还没建档”缺少解释；无课程提示直接展示工具名；缺地址时要求重新打开，却没有提供对应动作。建议保留标题与导航，用“发生了什么 + 可执行的下一步”组织，并与正常列表的内容边界对齐。

| 状态 | 推荐表达与动作 |

## 6. 建议的页面结构

### 6.1 设置页

建议阅读顺序为：**教学模式设置 → 教学动画配置摘要 → 基础字段 → 高级选项 → 保存反馈**。

| 区域 | 展示内容 | 处理方式 |
| --- | --- | --- |
| 页头 | 简短标题、自动保存说明 | 减少长解释；加载时不显示确定的运行结果 |
| 基础配置 | 工程目录、配置状态 | 路径保持完整可编辑；状态只表达已知事实 |
| 时长建议 | 动画建议时长上限及超出后的说明要求 | 显示单位和范围，明确针对一课成片的软性建议 |
| 高级选项 | 工程缺失时的行为、源码存放策略 | 默认折叠，可显示当前值摘要；不改变配置含义 |
| 反馈 | 字段级保存、失败和只读原因 | 沿用自动保存，不新增另一套整页保存机制 |

仅因为动画未配置就禁用所有高级项并无必要；可允许提前配置，但明确它们的适用条件。时长字段应按现有 schema 和协议表达成片时长，避免把一课动画时长、单个分镜时长和渲染预算混为一谈。

### 6.2 选课侧栏

建议阅读顺序为：**列表范围和数量 → 课程名称 → 当前有效状态与最近提交 → 必要时展开详情**。

| 条目部位 | 建议 |
| --- | --- |
| 主体 | 14px 课程名，最多两行；极长标题有完整查看方式 |
| 尾部 | 轻量进入提示；题量位置保持稳定 |
| 次行 | 一项主要状态、最近提交日期 |
| 详情 | 历史评估、失效原因、课程版本、题号登记异常 |
| 行状态 | hover、focus、当前课程分别可辨；状态变化不改变操作位置 |

条目存在嵌套操作时，应重新选择语义结构，避免在整行 `button` 内放另一个可交互按钮。课程多时可以在后续增加本地搜索；筛选项必须能由现有可信数据确定。

### 6.3 课堂外壳

建议阅读顺序为：**返回课程列表 + 课程名 + 更多操作 → 作答与评估摘要 → 课程 iframe**。

主视区只保留经常使用且必要的操作。导出离线页、导入进度和重新加载适合放入“更多”；若真实使用频率表明某项非常常用，再将它移出。顶部摘要明确“已提交题数”“待批改记录数”等对象，避免不同比较口径的数字构成假进度。

导入导出数据格式、回调、下载行为和课堂桥保持现有契约。缩小工具栏不得以 CSS 缩放、滤镜或覆盖层改变 iframe 内部呈现。

## 7. 统一视觉规则建议

以下为待原型验证的起始规则，不自动替代现有 `DESIGN.md`。

| 维度 | 建议规则 | 限定 |
| --- | --- | --- |
| 主题 | 继续使用宿主明暗主题与语义令牌 | 不移植课程页纸色、宋体、朱红到宿主界面 |

| 间距 | 4px 为基础；内边距 12–16px，字段间 16–20px，组间 24–32px | 需与真实宿主密度匹配 |
| 边界 | 靠对齐与间距分组，必要时用弱分隔线或一级底色 | 避免每个字段套卡片、边框加阴影叠用 |

## 10. 证据缺口与需要纠正的假设

### 10.1 `openable` 不是单课可用性

服务端 catalog 顶层的 `openable` 检查的是 `sidebar_open` 工具是否存在，表示自动打开相关能力。测试台的 `unopenable` 却把第二条课程的 `lesson.openable` 设为 false，未模拟真实顶层字段。

手动选课走宿主 `sidebarRight.openTab`，不能依据顶层 `openable=false` 直接禁用课程行。因此两张截图相同不能作为产品打不开课程的证据；应先修正 fixture，再分别验证自动打开能力与手动打开失败。来源：[S3] 第 535–543、598 行；[S2] fixture 第 148–153 行；[S1] 第 1343–1361 行。

### 10.2 “页面缺题”文案不够准确

`missingPageIds` 实际是“课程页引用、但档案未登记”的题号；`unmappedQuestionIds` 是“档案已登记、但课程页未引用”的题号。建议将前者在详情中写为“课程页中的部分题目尚未登记”，避免误导成 HTML 缺失题目。该提示涉及课程作者维护，普通学习视图应降低权重。来源：[S3] 第 575–577 行。

### 10.3 自动保存、默认值与重载不能只按文档概括

现有文档包含历史设计和实现约定，不能替代当前代码及宿主验证。自动保存、取消输入、清空字段、恢复默认值应分别检查；尤其不要把“清空草稿”直接等同“将已存配置重置为默认”。本次不修改这些保存行为。

“建议时长上限”的约束对象已由配置 schema 与动画协议确认：前者第 28 行说明一节课动画的软性上限，后者第 87、124 行要求量成片时长并在超出后写明理由。现有设置页使用“分镜超过 N 秒”的表达需要纠正；后续仅统一宿主界面文案，不改动画规则。来源：[S9]。

### 10.4 现有检查不构成全面设计合格证明

上一轮源码样式 lint 返回 0 FAIL／1 WARN，WARN 对应路径等宽字体，有合理用途。这只能说明未触发其大部分静态规则，不能证明界面美观、对比度合格或所有操作可用。本次 96 张渲染也不能替代真实宿主走查。

本文不提供审美总分或用户效率提升百分比，因为没有真实用户测试及足够依据。
