## 用户提出的目标

- 同一工作区支持多个教学集合，用于多次学习和内容分类。
- 仅主要课程页面显示浏览进度，再次打开保留进度；选课入口和集合层面展示进度。参考页、术语表与速查页不跟踪。
- 设置页提供默认值；选择教学模式预设时，在 DSH 对话框内显示可折叠的教学设置。
- 初期包含事实核查四档（不核查、宽松、适中、严格）与讲解深度三档（浅显、适中、深入）。核查档位影响子代理数量和来源分工；菜单需要允许未来扩展。
- 新增界面尽量使用动效，复用现有素材，提高审美；本轮不扩大教学视频需求。

## 第一轮已确认决定

1. 集合作为独立学习上下文，可用于分类，也能区分初学和重学；同一课在不同集合中的学习历史互不覆盖。跨集合复用固定内容版本，详见第二轮决定。
2. 百分比称为“阅读进度”，评估/掌握继续独立展示。
3. 设置页默认值用于新会话；对话内修改仅覆盖当前会话并在重开后保留，不反写全局默认。
4. “不核查”关闭专门的事实核查子代理，包括当前材料盲审；保留作者基本自查、材料出处要求与页面结构检查。其它档位的代理数、来源与交付规则见后续已确认决定。
5. 动画优先用于集合切换、折叠、滑块档位和进度变化；复用宿主样式与现有资源，课程教学动画继续按内容需要使用。
6. 用户收窄范围：只跟踪主要课程页面；参考页、术语表与速查页不考虑。

用户补充：核实宿主接口，尽量复用宿主接口。不以相邻插件的会话头按钮冒充输入框嵌入。

## 宿主接口调查

核对对象为本机已安装 DSH `0.2.1-rc.5`，不是对所有声明兼容版本的保证；尚未做真实宿主接入验证。详见[接口核实报告](../reports/2026-11-04-host-extension-interfaces.md)。

- **正式插槽已确认**：`@deepseek-ai/dsh-client-ui-conversation/lib/types/client/contract/slots.d.ts:300-327` 声明 `conversation.input.dock`（输入卡上方、全宽、会话作用域）、`conversation.input.overlay`（卡内浮层）、`conversation.composer.dock`（卡下方）、`conversation.input.left/right`（工具行）。实际客户端在 `lib/client.js:17907` 将 input.dock 放在输入卡之前。
- **已选接入位置**：在 input.dock 注册教学偏好折叠区，位于输入卡上方，复用宿主 DisclosureRow 与图标，不替换整个 composer。默认收起，只显示“教学设置”。
- **预设识别**：宿主客户端会话投影包含 agentPreset，正式预设控件本身读取这一信息。实际接入应使用宿主状态接口与包声明身份，不靠可翻译的显示名称猜测。
- **动态提示词**：宿主系统提示词 provider 每次 assembly 计算，本插件也已有动态变量 provider；会话覆盖可以在请求时进入提示词，不应沿用动画配置的重启要求。
- **持久化设施已找到**：没有通用 session metadata setter；可评估宿主 storage.domain 与插件受控 RPC。它保存宿主侧会话偏好，不能与教学根可搬迁状态混为一体；后端可用性尚未运行验证。
- **素材已找到**：宿主 primitives 导出 DisclosureRow、Button、相关图标；没有现成 Slider，可使用原生离散 range 和宿主主题。DisclosureRow 不自带高度过渡保证，必要动效由插件补充。
- **仍需核实**：真实宿主集成、storage.domain 后端、primitives 渲染及最低支持版本兼容性。

用户接受 Q7-Q10、Q12-Q14；Q11 按用户指定改为弹性人数。

| 编号 | 问题 | 已确认决定 |
| --- | --- | --- |
| Q7 | 同一课如何在多个集合中复用？ | 加入时复用并固定当时的课程内容版本；学习历史独立。一个集合的后续改课不自动覆盖另一个集合，升级版本需显式选择。 |
| Q8 | 页面如何度量浏览和续读？ | 分开保存历史最远浏览位置与最近停留位置；进度按前者计算、重开恢复后者，向上回看不降低进度。直接跳到末尾可能达到 100%，因此只称浏览/阅读进度，不表示掌握。 |
| Q9 | 集合百分比的分母是什么？ | 按当前已加入的主课程等权平均，不按正文长度加权，也不自动把尚未生成的计划课计入。新增课程可能降低集合百分比；空集合显示暂无课程。 |
| Q10 | 任务进行中调整滑块何时生效？ | 每次用户请求开始时固定本次偏好；调整从下一次请求生效，不取消或重启正在进行的生成与核查。 |
| Q11 | 核查四档如何分工？ | 用户指定人数：不核查 0 个、宽松 1 个、适中 1-2 个、严格 3-4 个。保留材料一致性、独立来源及反例/推导的分工方向，默认适中。人数分配与失败交付见第三轮，按需交叉复查见第四轮。代理数量不等于可靠性证明。 |
| Q12 | 讲解深度控制什么？ | 浅显优先直觉与最小例子；适中增加核心原理、必要公式和常见错误；深入增加推导、边界与反例。默认适中；不因深入而自行扩大课程主题或默认增加核查代理。 |
| Q13 | 旧课程与旧历史如何归属？ | 归入一个默认集合，保留原有作答与评估；没有历史阅读数据时显示暂无阅读记录，不根据作答反推阅读百分比。迁移与回滚按下文实施方案验证。 |
| Q14 | 偏好与学习档案是否具有不同的搬迁范围？ | 会话偏好跟随宿主会话，课程/集合/阅读记录跟随教学工作区；仅复制教学工作区不复制对话内滑块覆盖。优先复用宿主持久化设施，实际后端能力需集成验证。 |

## 核查执行规则与成本边界（已确认）

- 默认完成所选档位的首轮核查后即可收敛，不为了流程完整而自动复查。
- 仅在关键事实存在争议、核查意见冲突或关键断言经过实质修正时，考虑一次定向复查；只提供相关段落、出处与问题清单，不重新发送整个对话或整课全部材料。
- 有多个代理时，以交叉分配执行复查：A 看 B 的核查项或对应修正，B 看 A 的核查项；不再新开整批代理，也不要求所有代理两两互审。只有一个代理时才允许它自查。
- 同一次课程生成最多自动进行一轮按需复查，不自动递归多轮。仍无法收敛时使用已确认的待核/未完成交付方式；用户明确要求再次核查时作为后续请求处理。此轮次上限已在 Q30 获用户确认。
- 事实核查人数范围指本次生成中参与核查的不同子代理，失败替补计入上限。复查复用现有代理的身份做交叉任务，不借复查突破档位人数上限。
- 核查代理仅接收课程、所需材料与分配任务，保持现有无完整对话上下文的盲审边界。记录真实来源与实际完成情况，不用“几个代理赞同”替代证据。
- 有明确错误先修复或删去；未能核实的断言标待核或删去；可带核查未完成状态交付，并保留简短摘要与可展开详情。

## 数据与接口实施建议

以下为落实已确认行为的工程方案，需在编码前结合宿主接口探针定稿。

| 对象 | 归属与关键边界 |
| --- | --- |
| 集合与课程清单 | 保存在实际教学根的 `.dsh-teach-me/` 范围，按既有 workspaceId 隔离；集合持有稳定身份、名称、归档状态与课程版本引用。 |
| 课程内容版本 | 保留可再次打开的固定 HTML、题目与所需内容资产，不能只保存版本号再读取可变的最新版文件。内容版本与样式/构建产物变化分别处理；具体分类和指纹规则要可测试，不凭模型临时猜测。 |
| 阅读状态 | 以工作区、集合、课程及内容版本共同定位，分别保存历史最远浏览位置与续读位置。高频阅读写入与正式作答/评估证据分开处理，不能将滚动事件解释为掌握证据。 |
| 作答与评估 | 集合归属贯穿题目提交、导出/导入、评估、复习与展示；不能只在选课页过滤，而底层继续按 lessonId 汇总所有集合。旧记录归默认集合，不丢弃原始证据。 |
| 会话偏好 | 新会话保存默认值快照，后续全局默认修改不悄悄改变已有会话；会话内修改只影响下一次请求。优先宿主 storage.domain，经受控接口读写；当前集合也由会话独立记住。 |
| 请求与课堂上下文 | 每次请求固定集合、偏好及相关版本；已打开课堂也固定原集合与版本。切换集合、改滑块或后台窗口事件不能重定向已有任务与提交。 |
| 核查结果 | 绑定具体课程内容版本及本次生成任务，保留档位、参与及完成情况、证据来源、问题、修正与实际复查记录。复用课程不伪造一次新核查，也不自动复制学习历史。 |

课堂进度沿用已有受控桥与 host 接口返回，扩展消息类型、身份校验和版本约束；不由沙箱页直接向任意路径写文件。继续使用能力票和宿主会话身份，不能只信任请求体自报的集合 ID。

进度保存使用节流、失焦/离开时尽力提交与幂等合并，避免每个滚动事件都写盘。历史最远值取最大值；续读位置只受最后一次主动阅读影响，恢复滚动与后台窗口不覆盖。页面过短无须滚动时，在实际呈现后可记为到达末尾；恢复位置优先稳定章节与相对位置，以适应纯排版变化。

## 界面与复用范围

- 设置页新增两个默认档位，均默认适中，沿用既有字段保存反馈；可按宿主设置行重新分组，不扩大为课程生成器配置后台。
- 教学会话的 `conversation.input.dock` 中提供默认收起的“教学设置”；展开显示当前集合选择/新建、核查四档、深度三档及下一次生效提示。后续选项按分组扩展，不修改固定 DOM 或接管整个输入框。
- 选课页新增集合选择、管理入口、集合百分比及每课进度；暂无阅读数据保持明确文案。已归档集合放在可切换列表，空集合显示暂无课程。
- 课堂顶部显示主课程阅读进度与必要的保存状态，作答/评估保持独立。核查详情可展开，不将完整报告注入讲义正文。
- 宿主内界面复用主题令牌、DisclosureRow、按钮及图标；离散滑块使用原生 range 配合档位文字。课程页保持既有讲义风格。
- 动效用于折叠展开、集合切换、滑块换档及真实进度变化，不循环闪动或模拟未发生的进度；尊重减少动态效果设置，保证键盘与触屏可操作。
- 本轮不覆盖参考/速查页、外部页面、PDF、视频播放进度、普通浏览器直开与离线 HTML 阅读同步，也不提供永久删除集合。

## 迁移、失败与回滚建议

- 只读查看不初始化、迁移或修复档案。首次明确创建/修改集合或发布课程等写入路径，才执行所需迁移；只读工作区显示既有数据及限制。
- 迁移前备份权威日志、工作区身份和本次会改动的课程引用/文件，记录格式版本；不能把 index 或 archive snapshot 当备份。
- 在已有锁和事务边界内保留原课程、题目、提交与评估身份，归入默认集合。迁移失败不留下新旧模型各写一半的状态，重复执行不复制证据。
- 降级旧插件前恢复迁移前备份并验证，不承诺旧版能理解新增集合事件或记录；只删除派生索引不能视为完成回滚。
- 设置失败恢复最近成功值；阅读失败保留当前内存位置但显示未保存与重试。未知后端能力不退化成跨会话丢失却仍标为已保存的实现。
- 纯样式改动保持进度，正文/题目/依据变化包括错字修正视作内容新版；显式采用后从零开始并保留旧版记录。

## 已确认行为对应的验收场景

- 同一课加入集合 A 与 B，在 A 阅读、作答或评估，不改变 B 的历史。
- A 后来修改课程内容，B 仍读取原先固定版本，除非显式采用新版本。
- 页面读至 80% 后回看至 40%，再次打开恢复约 40% 的位置，历史进度仍为 80%；直接跳到末尾允许记录 100%。
- 集合中两课均为 100%，新增一课为 0%，集合显示约 67%；空集合不显示误导性的 100%。
- 请求开始后调整深度或核查档位，本次请求保留原设置，下一次请求使用新值；其他会话不受影响。
- 不核查不派事实核查子代理；宽松 1 个、适中 1-2 个、严格 3-4 个。默认只在课程生成时自动核查，不强制复查；按需复查时多代理互查、单代理才可自查。
- 旧课程与原有作答、评估仍可访问；不存在的历史阅读数据不被伪造为已读百分比。
- 复制教学工作区携带集合和阅读记录，不隐式复制会话内滑块覆盖。
- 会话从集合 A 切换到 B，已启动任务和已打开课堂仍记录到 A；下一次请求使用 B。
- 复制集合的课程版本清单保持一致，学习历史为空；归档后可恢复，首版无永久删除入口。
- 采用内容新版后从零记录阅读，旧版历史仍可访问，旧版通过不直接变成新版通过。
- 普通答疑不自动启动核查代理；核查未完成的交付必须明确标识，已知错误先修正或删去。
- 教学模式折叠菜单默认收起且仅显示“教学设置”，展开后可操作具体选项。
- 纯外观改动不重置阅读；正文、题目或依据改动按内容新版处理，采用新版需显式选择。
- 设置保存失败回到最近成功值；阅读保存失败可继续阅读，但未保存状态与重试入口可见。
- 同一集合/课程/内容版本多窗口阅读，最远进度取最大值，后台窗口与自动恢复不抢占续读位置。
- 无记录的旧课计入分母并贡献零，同时显示无记录数量，不把有练习提交推断为读完。
- 归档集合可打开和续读，既有生成任务可完成，新课程生成前要求恢复。
- 核查摘要与可展开证据对应实际任务；未执行复查时不生成虚假的复查结果，也不产生全量两两互审任务。
- 同次课程生成最多自动进行一轮按需复查；不自动递归多轮，仍有争议时明确标为待核。
